# Area

Веб-приложение для создания планов помещений и просмотра панорам 360°. Объединяет редактор чертежей, карты этажей, маршруты и публичный просмотр проектов по ссылке.

## Возможности

- Проекты с несколькими этажами, отдельными планами, чертежами и панорамами.
- Редактор фигур: размеры, вершины, поворот, слои, копирование между этажами, отмена и повтор действий.
- Информационные, навигационные и статусные метки на плане.
- Просмотр панорам 360°, переходы между панорамами и сборка панорамы из фотографий.
- Построение маршрутов по помещениям и между этажами через лестницы.
- Workspace для размещения нескольких карт на общем холсте и объединения их в группы.
- Публичные ссылки на проект с доступом без авторизации.
- Мобильный интерфейс, сенсорное управление, светлая и тёмная темы.
- Статистика посещений, переходов и просмотров панорам.

## Запуск через Docker

Требуются Docker и Docker Compose. Выполняйте команды из корня репозитория.

Скопируйте настройки:

```bash
cp .env.example .env
```

В PowerShell: `Copy-Item .env.example .env`.

Запустите приложение:

```bash
docker compose up --build -d
```

С адресами и портами из `.env.example`:

- Приложение: [localhost:3000](http://localhost:3000).
- Документация API: [localhost:8000/docs](http://localhost:8000/docs).
- Проверка API: [localhost:3000/api/health](http://localhost:3000/api/health).

Остановка с сохранением серверных данных:

```bash
docker compose down
```

## Вход и доступ

Страница входа — `/login`. Предустановленные аккаунты:

- Администратор: `demo@spacemap.ru` / `SpaceMap123!`.
- Пользователь: `user@spacemap.ru` / `Viewer123!`.

Администратор создаёт и редактирует проекты, управляет Workspace и просматривает статистику. Пользователь открывает планы и панорамы в режиме просмотра. Регистрация создаёт аккаунт пользователя.

Для просмотра проекта по публичной ссылке аккаунт не требуется.

## Работа с проектом

1. Создайте проект и откройте редактор.
2. Нарисуйте план или загрузите изображение плана на странице карты.
3. При необходимости добавьте этажи через меню «Этаж».
4. Разместите точки и метки, задайте названия помещений и добавьте панорамы.
5. Для маршрутов между этажами добавьте лестницы и укажите целевые этажи.
6. Нажмите «Поделиться», чтобы получить ссылку для просмотра.

Workspace создаётся кнопкой «+ Workspace» на странице проектов. Карты добавляются из списка «Все карты» внутри Workspace. Группировка карт сохраняет их исходные проекты.

### Управление редактором

- Фигура создаётся протягиванием указателя по холсту. Многоугольник — последовательным указанием точек и нажатием на первую точку для замыкания.
- Маркеры выделенной фигуры изменяют её размеры; круглый маркер над рамкой отвечает за поворот.
- `Shift + клик` выбирает несколько объектов, `Ctrl + A` — все видимые объекты.
- `Ctrl + C`, `Ctrl + V`, `Ctrl + D` — копирование, вставка и дублирование.
- `Ctrl + Z`, `Ctrl + Y` — отмена и повтор; `Delete` — удаление; `Escape` — отмена текущего жеста.
- Колесо мыши перемещает холст, `Ctrl + колесо` меняет масштаб. Холст также можно перемещать зажатой средней кнопкой мыши.

На мобильных устройствах инструменты, свойства и действия открываются с нижней панели. Одним пальцем можно рисовать и перемещать объекты, двумя — перемещать и масштабировать холст. Удержание пальца на объекте открывает меню действий.

## Публичные ссылки

Кнопка «Поделиться» создаёт снимок текущего состояния проекта и загружает его вместе с изображениями на сервер. Ссылка вида `/share/<id>` открывает планы, чертежи, точки и панорамы всех этажей без входа в аккаунт.

Публичный просмотр не позволяет редактировать исходный проект. Изменения автора не обновляют ранее созданный снимок: после редактирования нужна новая ссылка.

Для доступа с другого устройства используйте адрес опубликованного сайта или доступный адрес сервера вместо `localhost`.

## Хранение данных

- Рабочие проекты, чертежи, точки, Workspace, аккаунты и статистика хранятся в `localStorage` браузера.
- Изображения планов и панорам рабочего проекта хранятся в `IndexedDB`.
- Публичные снимки и их изображения сохраняются на сервере в `data/shares`. В Docker каталог `data` находится в постоянном томе `project-data`.
- Файловый API сохраняет загруженные изображения в `data/media`.

Локальные проекты и аккаунты не синхронизируются между браузерами. Очистка данных сайта удаляет локальную рабочую копию. Публичные снимки сохраняются независимо от браузера автора.

Вход и проверка ролей реализованы на клиенте; серверной авторизации нет. Отдельный CRUD API проектов и реестр загруженных файлов используют память процесса и не служат постоянным хранилищем рабочего редактора.

## Локальная разработка

Требуются Node.js 22.12 или новее и Python 3.11 или новее. Клиент использует React, TypeScript, Vite и Tailwind CSS; сервер — FastAPI и OpenCV; просмотр панорам — Pannellum.

### Backend

Linux и macOS:

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

PowerShell:

```powershell
cd backend
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

### Frontend

В другом терминале из корня репозитория:

```bash
cd frontend
npm ci
npm run dev
```

Приложение доступно на [localhost:5173](http://localhost:5173). Vite перенаправляет запросы `/api` на `127.0.0.1:8000`.

В PowerShell при ограничении выполнения `.ps1` используйте `npm.cmd` и `npx.cmd`.

## Настройки

- `FRONTEND_PORT` и `BACKEND_PORT` в корневом `.env` задают порты Docker Compose.
- `VITE_API_URL` задаёт адрес API при сборке клиента. Для локальной разработки его можно указать в `frontend/.env.local`; стандартное значение — `/api`. В Docker Compose этот адрес передаётся аргументом сборки.
- `MEDIA_DIR` и `SHARES_DIR` — переменные окружения backend для каталогов файлов и публичных снимков. По умолчанию используются `data/media` и `data/shares` относительно рабочей директории сервера.

Nginx в Docker обслуживает клиент, поддерживает прямое открытие страниц приложения и перенаправляет `/api` на backend.

## Проверки

Из каталога `frontend`:

```bash
npm run build
npm run lint
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты запускают Vite автоматически. Тест публичной ссылки с настоящим backend включается отдельно при работающем сервере на порту 8000:

```bash
PLAYWRIGHT_LIVE_API=1 npx playwright test tests/sharing-live.spec.ts
```

В PowerShell:

```powershell
$env:PLAYWRIGHT_LIVE_API = '1'
npx.cmd playwright test tests/sharing-live.spec.ts
Remove-Item Env:PLAYWRIGHT_LIVE_API
```

Тест создаёт публичную ссылку и проверяет планы, этажи и панораму в отдельном браузерном сеансе без авторизации.

Тесты backend в Docker:

```bash
docker compose exec backend python -m pytest tests -q
```

При локальном запуске выполните ту же команду `-m pytest tests -q` через Python виртуального окружения из каталога `backend`.

```text
  app/api/routes/    Маршруты API
  app/services/      Обработка проектов, файлов и склейка панорам
  app/repositories/  Хранилища проектов и файлов
  tests/             Тесты API и склейки панорам
docker-compose.yaml  Запуск клиента и сервера
```
